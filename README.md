# 声检 · 音频评测

用于中文播客的小批量音质验证。默认在本机运行，也支持用 Docker 部署到服务器。音频、自动结果和人工评分保存在运行设备，不调用外部模型或付费接口。

## 使用

1. macOS 安装 Python 3.12 或更新版本后，双击 **启动声检.command**；首次启动会安装运行组件。
2. 在 Chrome 浏览器打开 **http://127.0.0.1:8765**，方便回听音频。
3. 导入音频，选择评测模式，勾选多条音频，点击 **批量检测**。
4. 在结果页点击时间标记回听，填写人工评分，再导出 CSV 评分表。

评测期间可在每条音频旁点击 **暂停 / 继续**。勾选多条后使用 **暂停所选 / 继续所选**；清除勾选后可 **暂停全部 / 继续全部**。暂停会让出执行名额，已完成的评分窗口保留；服务器重启后仍保持暂停。暂停后切换上方评测模式再继续，会停止所选记录的旧模式并使用新模式重新计算；模式相同时保留断点。

支持一次多选或拖入多条音频，并在导入期间继续追加；逐条上传，显示真实传输百分比、大小和服务器确认状态，单条失败继续后续文件。单条最多 200 MB、时长小于 4 小时。按真实音轨识别，支持当前 FFmpeg 能解码的本地音频及视频音轨，包括 MP3、WAV、M4A/AAC/ALAC、FLAC、OGG、OPUS、WMA、AIFF、CAF、AMR、WebM、MP4 等，也接受无扩展名或自定义扩展名的有效音频。损坏、加密、没有音轨或解码器不支持的输入会提示原因。

网页在评测期间也能准备兼容 MP3 回听，显示真实准备和加载进度。首次完整加载后保存到浏览器，切换音频、刷新及重新打开同一地址时复用；服务器副本也会保留，避免重复转换。浏览器禁止存储或空间不足时会提示，刷新可能重新加载。回听副本为 256 kbps MP3，有压缩损失；细致音质复核可下载原音频。自动评分始终使用原文件，回听转换不修改原音频、自动结果或人工评分。

每条音频和结果页可点击 **删除**，勾选多条后使用 **删除所选**。确认后停止相关任务并删除所选原音频、自动结果及人工评分，无法撤销；相同内容的其他记录保留。

## CentOS Docker 部署

代码仓库：[renzhonghua8/audio-review](https://github.com/renzhonghua8/audio-review)。服务器版采用 **8001** 端口，可下载 GitHub 预构建镜像，不在已有服务的宿主上构建。默认独立容器、0.5 核 CPU / 自动选择 768 或 1024 MiB 内存（另需 512 MiB 宿主余量）、最多同时评测 2 条、其余排队；检测端口和容器名冲突，自动识别实际网卡 IP，不重启 Docker 或修改其他服务配置。完整命令及资源边界见 [Docker 部署说明](Docker部署说明.md)。模型随镜像提供。

默认升级需等待任务完成或完全暂停。需要中断声检任务后升级时，可使用 `--upgrade --stop-first --interrupt-tasks`；仅跳过任务队列检查，原音频与已保存评分保留，未完成任务可能需要重新检测，资源与原服务保护继续生效。

## 已实现

- 多文件导入队列、真实上传进度、逐条确认、失败明细及重试；导入期间可追加文件，也可先检测已导入音频。
- 勾选/全选批量检测、默认同时评测 2 个不同文件，单独显示进度，其余自动排队。
- 单个、所选及全部任务暂停/继续；保留评分进度、释放执行名额，并支持重启后继续暂停任务。
- 暂停后切换模式再继续；新模式重新计算，旧模式停止，相同模式继续断点。
- 单条和勾选批量删除；取消对应任务并清理数据，保留相同内容的其他记录。
- 默认全量快速模式；另有快速抽样和全量精细模式。
- 相同音频内容、模式和评测版本复用自动结果，人工评分保持独立。
- 单次解码同时生成原始声学与模型支路；网页只获取当前音频的完整片段数据。
- 全量声学检测：平均电平、近满幅样本、低能量片段、采样率和声道。
- **真实 DNSMOS P.835 普通模式**预测：人声音质 SIG、背景质量 BAK、整体音质 OVRL，保留逐窗口结果、P10 和最低分。
- 波形与时间标记回听、播放倍速。
- 评测期间准备兼容回听、真实进度、完整加载后保存；服务器和浏览器复用副本，支持下载原音频。
- 现有 7 个维度的人工评分，支持不适用、备注、评分人，自动与人工结果独立保存。
- 盲听模式隐藏音频文件名；盲听状态下导出的 CSV 也隐藏文件名。
- 结果刷新后保留，CSV/JSON 导出。
- 切换样本或盲听模式保留当前页面内的评分草稿；刷新、关闭网页前需点击保存。

## 速度实测

本机 CPU 对同一段 155 秒公开语音预热后单次评测：全量精细 37.06 秒（147 个窗口），全量快速 4.62 秒（18 个窗口），约快 8 倍；快速抽样 3.77 秒（14 个窗口，覆盖 120 秒）。这是单机流程基准，实际耗时受服务器、音频时长和并行负载影响，不代表模型准确率提升。详见 `验证说明.md`。

## 评分边界

本版本自动评测**音质**。自然度、真人感、愿继续听、声音区分度、口音情绪和是否怀疑 AI，当前由人工评分，不生成未经验证的自动分数。没有安装大型音频语言模型，也没有做转写或说话人识别。

DNSMOS 输出是质量预测值，不代表真人或 AI 来源，也不等同于你的业务评分标准。需用中文播客和人工评分验证。背景音乐可能影响背景质量分，低分或声学提示需要回听确认。

基础声学检查覆盖全量音频，保留原始采样率、声道和电平，不先降噪或归一化。模型支路转换为 16 kHz 单声道，以 9.01 秒窗口评分，逐窗口进行官方多项式校准。本应用将校准分数截断至 1–5，再计算均值、P10 和最低值；范围限制是应用额外处理。

默认“全量快速”用连续约 9 秒窗口覆盖全段，尾部也会评分。“快速抽样”用相同密度覆盖开头 1 分钟和中段 1 分钟；不足 2 分钟时评测全段。“全量精细”按 1 秒滑窗对全段密集评分，适合复核短时问题。快速与精细的均分、P10 和最低分可能不同；快速模式不保证与密集滑窗等价。报告记录实际区间、步长及窗口数。低于 -55 dBFS 的低能量窗口跳过；没有有效窗口时评分为空。短于 9.01 秒的音频按官方实现重复填充，并明确提示可信度较低。

当前人工评分保存的是每条音频的一份可修改记录；正式多人标注及听者间一致度分析需扩展为独立标注记录。自动与人工音质差值仅用于参考，不自动拟合业务评分。

## 运行与数据

启动程序默认在项目的 `work` 目录创建 Python 环境和 `audio-review-runtime` 数据目录。其中 `uploads` 是音频副本，`reviews.sqlite3` 保存结果与暂停状态，`models` 是已校验的模型缓存，`playback` 是可重建的兼容回听缓存。Docker 默认使用容器 `/data`，挂载到宿主 `/opt/audio-review/data`。解码产生的大体积临时 WAV 会在暂停、完成或失败后清理，暂停时只保留小型 JSON 检查点；继续评测需要重新解码原文件，已完成的模型窗口不重复计算。

搬到其他目录时，启动程序默认在项目内的 `work` 创建运行环境和数据。首次安装 Python 依赖需要网络，安装好后可离线运行。服务仅监听 `127.0.0.1`，无需账号。

开发运行：Python 3.12+，安装 `requirements.lock.txt`，然后执行 `python app.py --install-model` 和 `python app.py`。可用 `AUDIO_REVIEW_DATA_DIR` 指定数据目录，`AUDIO_REVIEW_PYTHON` 指定启动所用 Python。`AUDIO_REVIEW_WORKERS` 控制同时处理的文件数，`AUDIO_REVIEW_MODEL_THREADS` 控制音质模型线程数，本地默认均为 2、允许 1–8；Docker 默认 2 个评测任务、1 个模型线程。768 MiB 部署最多 2 个任务，模型线程固定为 1；始终只使用一个 Web 服务进程。

服务端回听缓存默认 1024 MiB，已生成文件不会自动淘汰。可使用 `AUDIO_REVIEW_PLAYBACK_CACHE_MB` 调整至 512–16384 MiB；达到上限后保留旧副本并提示，删除最后一条内容引用时会清理对应副本。浏览器保存按访问地址隔离，其他浏览器的离线副本需自行清理网站数据。
